# 把 RepoLens 变成你能讲清楚的项目

## 适合当前版本的项目描述

RepoLens 是一个使用 Python、Typer、Pydantic 和 GitHub REST API 实现的仓库静态分析工具，支持远端提交和本地目录，提取依赖声明、Python AST 符号和导入关系，生成带源码证据的中文 Markdown / JSON 报告。工程实现包括读取预算、异常处理、离线测试及跨平台 CI 配置。

项目使用 AI 辅助开发。只有在你实际阅读、验证并参与改进后，才把相应工作写成自己的经历；不要写“独立从零研发”或虚构用户规模、准确率、性能提升。

## 用 C++ 知识理解实现

| Python 概念 | 对照理解 |
| --- | --- |
| Pydantic Model | 类似带输入校验及序列化的结构体 |
| `with GitHubSource(...)` | 类似 RAII，离开作用域关闭 HTTP 连接 |
| `ast.NodeVisitor` | 类似访问者模式，按节点类型遍历语法树 |
| `scope` 列表 | 栈；进入类/函数压栈，离开时弹栈 |
| 模块 import 边 | 有向图，节点是文件，边代表语法层的依赖 |
| `MockTransport` | 注入假的网络层，在不联网时测试分支行为 |

## 三次短阅读

1. **20 分钟：跑通离线示例。** 打开 `examples/demo_repo`，先预测会识别出哪些类、函数和入口，再对照报告。
2. **30 分钟：跟一条调用链。** 从 `cli.analyze_command` 跟到 `local_snapshot`、`analyze`、`markdown`。重点解释为什么获取和解析分开。
3. **30 分钟：改一项有边界的小功能。** 例如为 `.mjs` 增加 JavaScript 统计，或支持一种新配置文件。补一个有意义的测试并提交 PR。

## 面试/自检问题

- 为什么先固定 commit SHA，而不每次直接从 main 读取文件？
- 为什么不能把 `a.run()` 的文本出现次数当成准确调用图？
- 如何区分“没找到测试”和“测试没有被扫描到”？
- 为什么公开仓库也会碰到限流？文件预算和请求预算有什么区别？
- 本地读取为什么要跳过符号链接？这是否等同于安全沙箱？
- 你怎样证明工具没有执行目标仓库代码？测试还存在哪些覆盖盲区？
- JSON 为什么带 schema_version？以后改变字段结构会影响谁？

## 验证增量读取

为同一个公开提交指定专用缓存目录，连续运行两次。比较两份 JSON 的 Blob 网络读取、命中次数、304 次数和 HTTP 请求数。再缩小文件预算，检查清单状态和候选文本读取状态。
